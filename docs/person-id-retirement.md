# 人物 ID 撤除政策

2026-10-13 使用者要求：舊人物 ID 在所有引用更新後撤除。繁體介面與 JSON 不應永久保留一人多個 ID 或過時相容入口；過往版本由 Git 歷史回查。

2026-10-18 使用者再確認：ID 是當前資料的內部引用。每項關係保留兩端 ID，每人 JSON 納入本人在任一端的同一筆來源記錄；正文人物標記及登記證據雙向對應。因此改號時應追蹤並更新全部入向、出向及其他引用，不另維護永久舊號對照或轉址。遷移中的暫存對照可供本次核對，完成後不作公開查詢資料。外部使用者每次重新搜尋、辨識並選取當前人物；外部曾保存舊 ID 不構成相容性要求。史料、身份辨識與爭議取捨的證據繼續保存，普通 Git 歷史亦保留，無須另立 ID 變更日誌。

執行順序：先依逐篇上下文與引文確認同指，指定保留 ID，再更新人物標記、親屬、稱號、地望、生卒、身份取捨、家族組裝與索引；驗證所有端點、引文、Unicode 錨點與生成正文後，移除舊人物登記、舊 JSON 及別名。不得為刪號而合併未證實同人的候選；同指不消除來源間的血緣、紀年或任職異說。

第一批格式別名：目前 5556 個舊格式別名已從有效 corpus、registry、家族組裝和姓名引文引用中撤出，現行人物登記不再保留 `id_aliases`。生成器清除不在目前人物或組裝集合內的過時 JSON。身份判斷尚未確定的獨立候選繼續分存。

待身份整併：目前同指決定的傳遞閉包為 6659 個集合，覆蓋7492個來源候選，其中833個候選ID需要在更新全部引用後撤除。這是目前盤點，仍須逐項排除身份衝突、檢查父系 ID 及重建索引，不宣稱已完成。身份證据保留來源的提及 ID、精確引句、決定 ID 與審閱狀態，不靠被刪人物 ID 作唯一證據鍵。

## 身份接合退休保留集合

非父系的同人接合，以 `editorial_annotation_rekey_receipt` 的 `identity_decision_id` 綁定一項實存跨篇身份判斷，`retired_person_ids` 僅作不可重用的保留集合，不是舊號轉址、別名或查詢端點。不得為了退休憑據而建立家族組裝。

此窄類型不混用 `family_id` 或命名空間欄位；當前人物須仍在登錄，退休號須已撤離登錄與別名。未知、混型、缺少身份證據的憑據拒絕處理。既有命名空間與家族退休類型保留原規則。人物公開包不另複製此退休集合；原提及錨點、身份判斷ID與引文則保留。
