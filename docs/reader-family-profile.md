# 閱讀器人物卡片與家族資料

人物卡片及完整人物頁共用同一呈現。生卒與親屬放在來源篇章摘要之前；配偶與子女分別列出，不從配偶名單推定生母。

`data/corpus/profiles/` 現為來源包中各已發人物 ID 的可讀資料投影，不再只匯出年表命中的人物。多個 ID 可能依暫定同指決定代表同一人，檔案數不是不同人物數。原來源、判讀、相反記錄及完整資料包仍保存於 CBR。

`person_ids` 列明已記錄的同指範圍；`relations` 保存涉及該範圍的雙向直接陳述；`preferred_relations` 保留來源組裝器既有取捨。卡片用 `assets/person-family.js` 逐檔讀取直接關係，追溯父、祖、曾祖。不儲存預接的祖先名單，不以人物 ID 字尾判定親屬或排行。明記祖父而闕父時，父欄留闕，祖欄照錄；循環停止該分支。相反父系主張並列，不任選第一條。

出生、死亡僅採 `life_events`；持職紀年不能充作生卒。原紀年及西元換算各自保留；暫定日期選擇保留異說。`age_assertions` 是來源報齡，不能自動改成享年、反推出生年或指定計歲方式。沒有記錄就顯示未詳。

姓名組件由 `data/corpus/profile-names.json` 保存精確來源及可撤回判讀。首批包含秦始皇與平原君；其餘保留人物來源標籤，不機械拆姓與名。秦始皇依〈秦始皇本紀〉「名為政，姓趙氏」呈現趙政；頂部稱號是人物辨認用稱，不代表該敘事時點已持有皇帝稱號。來源中的代詞、官稱與別名仍可展開核讀，不把所有來源稱呼都當成另一個個人名字。

此版尚未完成全庫姓名組件、來源報齡及逐段有效稱號時點的整理；不得以介面欄位存在聲稱資料已齊備。閱讀器沒有 AI 呼叫。
