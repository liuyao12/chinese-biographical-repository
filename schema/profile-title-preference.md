# Default profile title preference

`profile_title_preference_set` is an explicit editorial presentation choice, not a personal-name component, authority rank ordering, date-specific office, or tenure assertion. Each current canonical person has at most one decision across the native catalogue. No decision means no `default_profile_title` output field; legacy presentation remains unchanged.

A decision references a validated native title holding, one attestation belonging to it, and its exact work/book/source/chapter/paragraph/person-mention/character coordinates. There is no free `title` or date field. `scope=timeless_profile_heading`, `temporal_claim=none`, `status=editorial_provisional`, and `human_reviewed=false` are mandatory in this AI-reviewed first implementation. Source kind/mode/title are resolved from the holding, not selected independently. All original evidence and effective periods remain intact.

`profile_title_preferences.resolve` checks global uniqueness, current identity, retirement reservations, exact source evidence, and the existing `received_career_roles.holding_valid` finite source contract. Unknown holding grammars fail closed. This first implementation handles native `title_holding_assertion_set` records supported by that validator; historical-table holders and bare `attestation` modes require a later explicit quoted-appellation contract and are not silently treated as service. It does not alter legacy display for these records.

Posthumous grants, enfeoffments and names, acting duties and self-proclamations retain their recorded role. The card/full page visibly labels the selected mode and editorial choice and links to the exact source subject. No composite title, lifetime assertion, investiture date or tenure end is inferred. Structured commentary challenges, unresolved identity/title source anchors and explicit same-holding non-assumption records are rejected. This is not an NLU detector of unrecorded historical disputes.

`PreferenceCatalog` holds the validated index only for one root-local load transaction. There is no process-global cache. Its row list cannot be edited; chosen record/chapter/holding dependencies are compared with snapshots and fixed raw-file SHA before reuse. New editorial data requires `load_catalog` again. Source-row dictionaries retain the legacy catalogue API, so callers must not repurpose an existing row into a new record type during a transaction. Such arbitrary in-memory restructuring is outside the immutable transaction contract. Plain externally supplied record lists receive full validation instead of cached trust. Unselected people use constant-time lookup without rescanning all holdings or receipts.

Native rekeys must update the decision's current `person_id` and all current structured endpoints through the existing rewrite machinery. Holding/decision/attestation/mention IDs and original source characters are stable. There is no old-to-new runtime alias or redirect in this model.
